Canal beta

Beta v0.15.0-beta.10

O beta é uma prerelease no GitHub: a próxima versão, já usável, que ainda pode mudar até virar estável. O comando padrão de instalação nunca instala um beta; você o escolhe fixando a versão. Este é o beta atual, e a tag dele começa com v.

O que muda na 0.15

O Nirvana entra só quando o pedido chama por ele

Na 0.15 o nrv init . escreve, por padrão, uma nota curta em AGENTS.md, CLAUDE.md e GEMINI.md, sem perguntar. Com ela o agente trabalha como trabalharia sem o Nirvana, e usa o Nirvana quando o pedido:

  • nomeia o Nirvana ("use o Nirvana para…", "via nirvana");
  • nomeia ou aponta uma das suas empresas, squads ou mind-clones ("minha empresa de lançamentos", "o squad de copy", "com a voz do Hormozi"), inclusive pelo nome de um pacote;
  • pede o trabalho, ou parte dele, em outro runtime ("use o Codex para revisar").

Para o Nirvana orquestrar todo entregável do projeto, diga "orquestre tudo neste projeto com o Nirvana". O agente roda nrv init . --orchestrators=always. Abra uma sessão nova para a mudança valer. Na 0.14.11 é o contrário: o padrão é always.

Perfis de desempenho

Só existem na 0.15. Um perfil ajusta várias configurações de uma vez:

PerfilEsforçoTeto de contexto por workerRevisão
maxxhighnenhum (padrão do runtime)toda entrega, até duas rodadas de correção
balanced (recomendado)high400 mil tokensquando uma regra pede
economymedium200 mil tokenssó quando você pede

Um perfil nunca escolhe o modelo; quem escolhe é a configuração do seu runtime. Uma configuração que você muda explicitamente vence o perfil.

Instale o beta

Os preparativos de cada sistema (o unzip no Ubuntu, o WSL) estão no guia de instalação. O comando do beta instala por cima de uma estável, se você já tiver uma, e mantém o seu conteúdo, os pacotes e as configurações.

macOS

No Terminal:

curl -fsSL https://gutomec.github.io/nirvana-os-engine/install.sh | NIRVANA_ENGINE_URL=https://github.com/gutomec/nirvana-os-engine/releases/download/v0.15.0-beta.10/nirvana-os-engine.tar.gz bash

Windows

No PowerShell, sem administrador. É uma linha só, com aspas simples:

$env:NIRVANA_ENGINE_URL='https://github.com/gutomec/nirvana-os-engine/releases/download/v0.15.0-beta.10/nirvana-os-engine.tar.gz'; irm https://gutomec.github.io/nirvana-os-engine/install.ps1 | iex

Se a janela continuar aberta no fim, rode:

Remove-Item Env:NIRVANA_ENGINE_URL

Enquanto a variável existir na janela, o nrv update e o setup de pacotes reinstalam exatamente esse beta. Se o PowerShell mostrar >>, uma aspa se perdeu na colagem: aperte Ctrl+C e cole a linha de novo.

Windows com WSL

Dentro do Ubuntu, com curl e unzip instalados:

curl -fsSL https://gutomec.github.io/nirvana-os-engine/install.sh | NIRVANA_ENGINE_URL=https://github.com/gutomec/nirvana-os-engine/releases/download/v0.15.0-beta.10/nirvana-os-engine.tar.gz bash

O seu agente de IA também precisa estar instalado dentro do Ubuntu.

Linux

Com curl e unzip instalados:

curl -fsSL https://gutomec.github.io/nirvana-os-engine/install.sh | NIRVANA_ENGINE_URL=https://github.com/gutomec/nirvana-os-engine/releases/download/v0.15.0-beta.10/nirvana-os-engine.tar.gz bash

Depois, feche o terminal, abra um novo e confira:

nrv --version

A saída mostra 0.15.0-beta.10. Um 404 no download quer dizer tag sem o v ou versão inexistente; as versões publicadas estão na lista de releases.

Escolha um perfil

Rodado num terminal interativo, o instalador pergunta o perfil uma vez. Pelo curl … | bash não há terminal para perguntar, então nada é gravado e valem os padrões do engine. Você escolhe depois pedindo ao agente:

"Coloque o Nirvana no modo economia."

"Quero qualidade máxima no Nirvana."

Ele roda, por exemplo:

nrv config set execution.profile economy --global

No macOS, no Linux e no WSL também dá para passar o perfil na instalação, no fim do comando do beta: troque bash por bash -s -- --profile=balanced.

Pacotes e atualizações

  • Pacotes. Instale como no guia. O setup de um pacote nunca troca o engine por uma versão mais antiga, então quem está no beta continua no beta.
  • Engine. nrv update (ou "atualize o Nirvana-OS") mantém você no canal beta: vai para betas mais novos e, quando a 0.15.0 sair, para ela. Nunca volta para a 0.14.
  • Um pacote. nrv update genesis-circle, com o slug do pacote. Em erro de licença, baixe o pacote de novo e rode o setup.

Projetos que vieram da 0.14

Um projeto preparado na 0.14.11 tem o contrato completo. Rodar nrv init . no beta troca esse bloco, no lugar, pela nota sob demanda; para manter a orquestração total, use nrv init . --orchestrators=always. As regras que você escreveu acima do bloco do Nirvana ficam.

Volte para a estável

  1. No Windows, abra um PowerShell novo e rode o comando abaixo. Se aparecer um erro dizendo que a variável não existe, pode ignorar. 
    Remove-Item Env:NIRVANA_ENGINE_URL
  2. Rode o comando estável do seu sistema. Ele instala a última estável por cima do beta e mantém o seu conteúdo, os pacotes e as configurações.
    macOS, Linux e WSL
    curl -fsSL https://gutomec.github.io/nirvana-os-engine/install.sh | bash
    Windows
    irm https://gutomec.github.io/nirvana-os-engine/install.ps1 | iex
  3. Feche o terminal, abra um novo e confira que nrv --version não mostra mais beta.
  4. Em cada projeto que você usou com o beta, rode nrv init . de novo. A 0.14.11 não reconhece a nota que o beta escreveu, então antes apague das instruções do projeto (AGENTS.md, CLAUDE.md, GEMINI.md) o bloco do beta, que começa na linha <!-- nirvana-os:on-demand-contract:v3 --> ou <!-- nirvana-os:invocation-contract:v4 -->, e deixe as suas linhas. Pelo agente: "apague o bloco do Nirvana escrito pelo beta nos arquivos de instrução deste projeto e rode nrv init de novo". Para continuar sob demanda, use nrv init . --orchestrators=on-demand.

Os pacotes continuam instalados. Para voltar ao beta depois, rode o comando do beta de novo.
