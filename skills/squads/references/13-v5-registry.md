# v5 registry — operational guide

## When to load

Intent: DISCOVER | EXECUTE | OBSERVE when the user mentions "registry",
"index", "rebuild", "auto-invalidation", or is diagnosing why a squad
does not show up.

## Protocol Reference

`SQUAD_PROTOCOL_V5.md` §23 (Global Registry and Indexing).
Registry schema: `core-schemas.json#/registry_squads`.
Implementation: `~/.claude/skills/squads/lib/registry.js`.

---

## Why the registry exists

In v4, discovery was `find ${SQUADS_DIR} ./squads -name squad.yaml` followed
by parsing each manifest. For 137 squads that is expensive and provides no
semantic index. In v5, the harness reads a pre-computed index:

```
${SQUADS_REGISTRY_PATH}
```

The registry is **cache, not source of truth**. The source remains the
`squad.yaml` files on disk. The registry is regenerated by
`scripts/index-squads.ts`.

### What the registry contains

```json
{
  "schema_version": "1.0.0",
  "generated_at": "2026-05-02T15:00:00Z",
  "host_protocol_version": "5.0",
  "squads_root_dirs": [
    "${SQUADS_DIR}"
  ],
  "squads": {
    "sales-funnel-masters": {
      "version": "5.0.0",
      "protocol": "5.0",
      "manifest_path": "${SQUADS_DIR}/sales-funnel-masters/squad.yaml",
      "manifest_hash": "sha256:...",
      "domains": ["marketing", "sales", "growth", ...],
      "capabilities": ["marketing.funnel.create", ...]
    }
  },
  "capabilities": {
    "marketing.funnel.create": [
      {
        "squad": "sales-funnel-masters",
        "description": "...",
        "domains": [...],
        "examples": [...],
        "not_for": [...],
        "fidelity_status": "experimental",
        "invoke": { "type": "workflow", "ref": "..." },
        "score_boost": 1.0
      }
    ]
  },
  "domains": {
    "marketing": ["sales-funnel-masters", "..."]
  }
}
```

## How it is generated

`bun ~/.claude/skills/squads/scripts/index-squads.ts`

Internally:

1. Walk over `${SQUADS_DIR}`, `${SQUADS_LEGACY_DIR}` (if set), `./squads` (depth ≤2).
2. For each `squad.yaml` found, parse + light validation.
3. Computes `manifest_hash = sha256(squad.yaml content)`.
4. Indexes by capability_id and by domain.
5. Applies the collision rule: local (`./squads`) > `${SQUADS_DIR}` > `${SQUADS_LEGACY_DIR}`. The last write per name wins.
6. Writes `${SQUADS_REGISTRY_PATH}` atomically (write-temp + rename).

### Equivalent Node command

```bash
node ~/.claude/skills/squads/lib/registry.js rebuild
```

JS API:

```javascript
const reg = require('~/.claude/skills/squads/lib/registry');
reg.scan();              // [{squad_name, manifest_path, manifest, hash}, ...]
reg.build();             // full registry object (without writing)
reg.write(reg.build());  // writes to ${SQUADS_REGISTRY_PATH}
reg.rebuild();           // scan + build + write
```

## How the harness consumes it

When the harness receives a brief, it:

1. Loads `${SQUADS_REGISTRY_PATH}` (lazy, cached in session memory).
2. Tokenizes the NL brief.
3. Runs BM25 over `description + examples + not_for` of all indexed
   capabilities.
4. Applies `score_boost` and the fidelity penalty (validated=1.0,
   experimental=0.85, drifted=0.5, retired=0).
5. Returns 1 of the 3 signals (Squad v5 §24): `MATCH_HIGH` (score ≥0.80 and
   gap ≥0.15), `MATCH_AMBIGUOUS` (score 0.60-0.80), `NO_MATCH` (<0.60).

v4 squads (without `capabilities[]`) **are in the registry**, but
`registry.capabilities` has no entries for them. Result: they remain
listable and manually activatable, but the harness does not discover them
by NL intent.

## Invalidation

The registry keeps a `manifest_hash` per squad. When someone edits a
`squad.yaml`, the hash changes. When the registry is rebuilt, it detects
the diff and reindexes only what changed (today the implementation does a
full rebuild — incremental is left for a next wave).

### Automatic hook (Claude Code)

Add to `~/.claude/settings.json` to reindex automatically after edits to
squad.yaml:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": {
          "tool": ["Edit", "Write"],
          "file_pattern": "*/squad.yaml"
        },
        "command": "bun ~/.claude/skills/squads/scripts/index-squads.ts --quiet"
      }
    ]
  }
}
```

### Manual invalidation

```bash
# Force rebuild (always safe, idempotent)
bun ~/.claude/skills/squads/scripts/index-squads.ts

# List everything in the registry
bun ~/.claude/skills/squads/scripts/list-squads.ts

# Filter v5 only
bun ~/.claude/skills/squads/scripts/list-squads.ts --proto 5.0
```

## Troubleshooting

### "Squad não aparece no `*squad list`"

1. `bun ~/.claude/skills/squads/scripts/index-squads.ts` — forces a rebuild.
2. Confirm that `squad.yaml` is in `${SQUADS_DIR}`, `${SQUADS_LEGACY_DIR}` (if set) or
   `./squads` (depth ≤2 — `${SQUADS_DIR}/foo/squad.yaml` works,
   `${SQUADS_DIR}/foo/bar/squad.yaml` does not).
3. Check that the YAML parses: `node -e "console.log(require('yaml').parse(require('fs').readFileSync('squad.yaml','utf8')))"`.
4. Check that the YAML has `name:` (mandatory registry field).

### "Capability não é descoberta pelo harness"

1. `*squad validate <name> --report` — check for capability errors.
2. Check that `${SQUADS_REGISTRY_PATH}` has an entry under `capabilities.<id>`.
3. Check whether the `examples[]` cover the user's actual phrase (BM25
   ranks by token overlap with description+examples+not_for).
4. If another squad has the same capability_id with a higher `score_boost`
   or a better `fidelity_status`, the harness picks it. Use `not_for[]`
   to differentiate.

### "Registry obsoleto após várias edições"

Symptom: `*squad list` shows 137 squads but `${SQUADS_REGISTRY_PATH}`
still says 100. Solution:

```bash
bun ~/.claude/skills/squads/scripts/index-squads.ts
```

Idempotent. Always safe.

### "Erro ao parsear squad.yaml de uma squad antiga"

The registry is robust: it logs a warning to stderr and skips the
malformed squad.yaml. Other squads remain indexable. See stderr for
details.

```bash
bun ~/.claude/skills/squads/scripts/index-squads.ts 2> /tmp/index-warnings.log
grep WARN /tmp/index-warnings.log
```

### "Registry diz que squad existe em v4 e v5 simultaneamente"

The collision rule guarantees that only one wins (the last, in order
`${SQUADS_LEGACY_DIR} → ${SQUADS_DIR} → ./squads`). If you want to keep both
versions but with distinct names, rename the v4. If you finished the
migration, delete the v4.

## File locations

| File | Purpose |
|---------|--------|
| `${SQUADS_REGISTRY_PATH}` | Registry cache (generated) |
| `~/.claude/skills/squads/lib/registry.js` | Indexer (Node) |
| `~/.claude/skills/squads/scripts/index-squads.ts` | Bash wrapper |
| `~/.claude/skills/squads/scripts/list-squads.ts` | Reads registry, formats table |
| `~/.claude/skills/_shared/schemas/core-schemas.json#/registry_squads` | Schema of the generated JSON |

Zero external deps — uses only the Node stdlib + the vendored `yaml` module.
